Standup generator from git log.

Paste yesterday's commits, add what you're doing today and what you're stuck on, and copy a standup for Slack, Teams or Jira.

It runs in your browser. Nothing you paste is uploaded, saved or tracked. Close the tab and it's gone.

1. Get yesterday's commits

Run this inside a repo. It lists your commits from yesterday, on every branch, without merges:

git log --all --since=yesterday.midnight --until=midnight \ --author="$(git config user.email)" --no-merges --format='* %s'

On a Monday, look back to Friday instead:

git log --all --since="last friday" \ --author="$(git config user.email)" --no-merges --format='* %s'

Work in several repos? Use the loop in Write your standup from git log. The generator groups its lines by repo.

2. Paste, add today, copy

What the generator changes

  • Drops noise. Empty lines and merge commits ("Merge branch…", "Merge pull request…") go.
  • Strips prefixes. List markers and conventional-commit prefixes such as feat:, fix(sync): and chore: are removed, and the first word gets a capital letter.
  • Keeps ticket IDs. SYNC-142 stays, so your team knows which ticket you mean.
  • Collapses duplicates. --all can list the same commit twice after a rebase or cherry-pick. Exact repeats become one line.
  • Groups by repo. Lines from the multi-repo loop, or written as [repo] message or repo: message, are grouped under each repo.
  • Reads other shapes too. Output from git log --oneline or plain git log works.

It doesn't rewrite your messages. "Add retry wrapper" is still an implementation detail. For turning commits into outcomes, see the tips in the git log guide and the shapes in 12 standup examples.

Where this falls short

A generator can only tidy what git knows. Four gaps show up most weeks:

  • Work that isn't a commit. The review you gave, the bug you reproduced, the design call you sat in. None of it is in git log.
  • Follow-ups and blockers. Git doesn't know you've waited six days for staging access, or that you asked three times.
  • Other machines. The command only sees repos on the machine you run it on.
  • Monday after a holiday. "last friday" misses Thursday if Friday was a day off, and you have to remember to change the date at all.

Sill covers most of this. On the Mac, Sill reads the local git history of your repos (commit messages and times, never your code) and writes Yesterday, Today and Blockers from your commits, the tasks you finish and the follow-ups you log. Monday's standup looks back to Friday on its own, and the timeline keeps every day, so after time off you can copy a worklog for any date range.

Commits are read only by the Mac app, and they never leave that Mac. On iPhone, iPad and Apple Watch, Sill tracks the tasks you finish and the blockers you're waiting on, with receipts like day 6, asked 3×, and syncs them through your own iCloud. So a second machine's commits still need that machine, but your tasks and follow-ups are everywhere. No account, no server, no analytics.
